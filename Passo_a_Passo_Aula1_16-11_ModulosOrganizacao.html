Etapa 0 · O seu projeto está no Git?

Antes de apagar qualquer coisa, salvamos a Semana 5. O commit funciona só no seu computador: não precisa de GitHub.

ComandoO que faz
Get-ChildItem angular.jsonConfere se o terminal está na raiz do projeto. Se mostrar o arquivo, está no lugar certo. (No Git Bash, use ls angular.json.)
git statusMostra se a pasta já é um repositório Git e quais arquivos mudaram.

Cenário 1 · O git status listou arquivos ou disse nothing to commit

O projeto já tem Git (o ng new cria sozinho). Salve a Semana 5:

git add .Coloca todas as alterações do projeto na "área de preparação" do próximo commit.
git commit --message "semana 5 concluida"Cria um ponto de restauração com a mensagem informada. Se algo der errado hoje, dá para voltar a ele.

Cenário 2 · Apareceu fatal: not a git repository

O projeto ainda não tem Git. Crie o repositório local e salve:

git initTransforma a pasta do projeto em um repositório Git (cria a pasta oculta .git).
git add .Prepara todos os arquivos. O .gitignore criado pelo ng new já deixa a pasta node_modules de fora.
git commit --message "semana 5 concluida"Cria o primeiro ponto de restauração do projeto.

Cenário 3 · O Git pediu nome e e-mail (Please tell me who you are)

Acontece na primeira vez em um computador. Configure e repita o git commit:

git config --global user.name "Seu Nome"Define o nome que aparece como autor dos commits neste computador.
git config --global user.email "seu@email.com"Define o e-mail do autor (use o mesmo da sua conta do GitHub).

Cenário 4 · git não é reconhecido como comando

O Git não está instalado. Para não travar a aula, faça um backup manual: no Explorador de Arquivos, copie a pasta src do projeto para fora dele (por exemplo, Documentos\src-semana5). Instale o Git depois (git-scm.com).

Etapa A · Gerar pela CLI (para ver a CLI trabalhando)

Se o ng serve estiver rodando, pare com Ctrl + C. Depois, ainda na raiz do projeto:

ComandoO que faz
ng generate component core/layout/headerCria o componente Header em src/app/core/layout/header/ (4 arquivos: .ts, .html, .css, .spec.ts). Fica em core porque o cabeçalho aparece uma vez no site.
ng generate component core/layout/footerCria o componente Footer (rodapé), também em core.
ng generate component shared/components/page-headerCria o PageHeader em shared: um componente reutilizável por qualquer página.
ng generate module sharedCria src/app/shared/shared-module.ts: um NgModule que vai agrupar o que várias páginas usam.
ng generate component features/cursos/lista-cursosCria a página ListaCursos dentro da nova feature cursos.
ng generate service features/cursos/curso-serviceCria o CursoService (@Service()) dentro da feature cursos: ele vai guardar a lista de cursos.
ObserveAbra src/app/shared/shared-module.ts: a CLI criou um @NgModule com declarations: [] e imports: [CommonModule]. Os nomes gerados são os mesmos da pasta da aula: na Etapa B eles serão substituídos pelas versões preparadas.

TODO 1 · Aliases (@core, @shared, @features)

Arquivo: tsconfig.json (na raiz do projeto, fora da src) → dentro de "compilerOptions", depois de "module": "preserve"
    "module": "preserve",
    "paths": {
      "@core/*": ["./src/app/core/*"],
      "@shared": ["./src/app/shared/index.ts"],
      "@shared/*": ["./src/app/shared/*"],
      "@features/*": ["./src/app/features/*"]
    }

Atenção à vírgula depois de "preserve". Salve e ligue o servidor:

ng serve --openCompila o projeto, sobe o servidor em http://localhost:4200 e abre o navegador. Recompila sozinho a cada Ctrl + S.
Normal neste momentoO terminal ainda mostra erros como 'app-page-header' is not a known element e No pipe found with name 'cep'. Eles somem no TODO 3. O que deve sumir agora é o Cannot find module '@core/...'.

Regra: sempre que mudar o tsconfig.json ou o angular.json, pare o servidor (Ctrl + C) e rode ng serve --open de novo.

TODO 4 · Lazy loading (carregamento sob demanda)

Arquivo: src/app/app.routes.ts

Antes de mudar, abra um segundo terminal (botão + no painel do terminal) para não parar o ng serve:

ng buildGera a versão de produção em dist/ e mostra o tamanho dos arquivos. Anote o tamanho do main em Initial chunk files.

Agora troque o conteúdo de app.routes.ts por:

import { Routes } from '@angular/router';
// (os 3 imports de componentes que estavam aqui foram APAGADOS)

export const routes: Routes = [
  {
    path: '',
    loadComponent: () => import('@features/inicio/inicio').then((m) => m.Inicio),
    title: 'Início | Projeto SCTEC',
  },
  {
    path: 'alunos',
    loadChildren: () => import('@features/alunos/alunos.routes').then((m) => m.ALUNOS_ROUTES),
  },
  {
    path: 'contato',
    loadComponent: () => import('@features/contato/contato').then((m) => m.Contato),
    title: 'Contato | Projeto SCTEC',
  },
  // TODO 5 parte C entra aqui (rota 'cursos')
  { path: 'cadastro', redirectTo: 'alunos/cadastro' },
  { path: '**', redirectTo: '' },
];

Testar: no segundo terminal, rode ng build de novo. Agora aparecem os Lazy chunk files (inicio, contato, alunos-routes). No navegador: F12 → aba Network → filtro JS → clique no menu e veja o arquivo (chunk) baixar na hora.
